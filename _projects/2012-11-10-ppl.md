## Beyond Clean Code

I was going through my "Clean Code" phase while working on ppl. Unable to fully put the philosophy to the test at work, I crammed every idea I could from that book into this source code. The result was just about the most Java-like Ruby code you're ever likely to see.

In practice I found the architectural strictness to be an oppressive, inspiration-draining headwind with few practical upsides, and the experience helped me to grow beyond the "Clean Code" fixation. I consider myself fortunate to have learned this lesson relatively early in my career.

## Behavioural Test Automation

ppl was my first time maintaining something people actually used and cared about all on my own. Silly mistakes led to embarassing bug reports. Despite the ultra-orthodox TDD of my "Clean Code" mania I found it was more than possible for bugs to form in the spaces between the units of code.

In order to be able to ship new versions without anxiety I poured my heart into a comprehensive suite of Cucumber tests that exercised the end-to-end user-facing behaviour.

```yaml
Scenario: Remove a contact from the address book
  Given I am in an address book with a blank contact called bob
  And I run "ppl rm bob"
  Then there should be 0 contacts
```

Tests like these gave me the confidence to quickly push quick fixes without feeling a need to engage in manual exploratory testing of each release. This paid off handsomely once the project's honeymoon period wore off and I no longer had the motivation for that kind of work.
